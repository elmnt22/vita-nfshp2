## Findings while the Vita is busy (2026-11-24 afternoon)

- **Offloading is saturated.** In the pursuit window, collision helpers ran 10.8 of 112 pool tasks per frame. The async mirror job took 2.2 ms, but main waited 2.45 ms for it. No core has spare time, so G1 (view-1 scenery on a helper) would repeat the gather-lane no-go. G1 is demoted to last; work reduction comes first.
- **Audio.** 3.0 ms/frame = 2 pumps x 1.0 ms + 2 sound updates x 0.5 ms (two 60 Hz updates per frame). Pump music decode averaged 0.55 ms per pump, with 5-7 ms peaks (audio_step_peak 7.7 ms). **Done (built, untested on Vita):** music refill now runs on the audio worker. Expected about -1.1 ms/frame and no 7 ms audio spikes. Off switch: `music_main.txt`.
- **Discarded captures** (the second 60 Hz update per frame) cost 1.7 ms/frame. About 0.65 ms of that is HUD BeginFrame and about 0.4 ms is HUD layers. Skipping the HUD build there is *not* exact: bitmap strips bake the texture scroll at build time, so a skipped build would freeze a different frame's scroll. Shelved.
- **Setup/HUD** on presented frames: about 0.8 + 0.95 ms. This is a player-HUD cost, not a pursuit cost (the calm window shows 1.16 ms HUD).
- **Scenery emit** is already NEON-tight: 2.1 us per run, ClassifyBounds in inline asm. The *rejected* draws (models with alpha/depth-sort strips, which take the full RenderModel path) cost 1.35 ms for about 50 draws (27 us each). A mixed batch is the candidate: opaque runs batched, the rest per-strip. Exactness depends on per-texture command order; use the PC command-compare harness.
- **Census added (built, not run):** the `render.scenery_reject` line counts rejected models per render, by reason: model state, no texture, depth-sorted texture, flag 0x100, flag 0x40, not resident. The next Vita bench decides whether a mixed batch is worth building.
- CPU and GPU clocks are already at maximum (444/222/222/166).

## Game thread

### G1. View-1 scenery capture on a helper (expected -5 to -8 ms)
Extend the proven async-mirror path (`SceneryResources::AsyncCapture`, an aux EcstasyFrame merged at a fixed command position) to the main view:
- A helper runs view-1 scenery (its traversal, LOD hysteresis update and emit) into aux frame 1. The mirror job then chains after it, because it already waits on view-1 zones through `collectReady`.
- Main continues with view 1's world tail (NIS, sun, skids, movers, players, objects), solids, particles and HUD.
- The scenery commands are spliced in at their original position.

Research before coding:
- Audit what view-1 non-scenery capture reads from scenery state: LOD hysteresis, light contexts, `CaptureInstance` / projection pools, texture tables. Only the parts that can run before the merge may overlap.
- Splicing about 1000 commands of 168 B is roughly 1 ms of memmove on Vita. Prefer letting Gather walk command segments in order (no copy).
- Core 2 headroom is bursty. Measure the helper claim latency with `render.mirror_claim_histogram`. If the claim waits, main runs the job inline, so there is never a deadlock, only no gain.
- Verify: on PC, compare the commands with the serial path (`AsyncSceneryCommandsEqual`). Off switch `async_view1_off.txt`.

### G2. Cross-frame scenery emit reuse (expected -2 to -3 ms; also shrinks G1's helper job)
Emit is about 11.7 us per scenery draw, 476 draws in 5.6 ms.
- For a static instance whose batch, light key, clip class and strip-cull result match last frame, copy last frame's commands and refill only the instance (localToClip) and the projection pointers.
- Find which per-strip work dominates with the existing `render.scenery_emit_sample` (runs 1854, strip_tests 1674 per frame). The strip frustum tests are view dependent, so cache their result only when the instance bound is fully inside the frustum.
- Verify against `EmitOpaqueSceneryRunsReference` (the existing HP2_VERIFY_EMIT_RUNS harness).

### G3. Audio off the game thread (expected -1 to -2.5 ms)
`soundUpdate` plus `PumpAudio` took 3.0 ms per frame in the pursuit window. The update is wall-clock gated (8 ms), so it never feeds gameplay state.
- Step 1: run `PumpAudio` (0.9 ms) on the audio worker (core 2, priority 180) through a hand-off.
- Step 2: snapshot the car and sound inputs at the end of update, so `carSoundUpdateAll` and the soundscape can run on the worker. Audit the reads: car state, collision contact audio, speech.

### G4. HUD and setup capture (expected -1 to -1.5 ms)
HUD (1.3 ms) and setup (1.6 ms) are player-only costs; the demo bench shows 0.15/0.2 ms.
- Add fine timers per layer, `RenderModels` and TrackMap.
- Then cache layers whose inputs are unchanged, or skip empty layers cheaply.

### G5. Particle capture (expected -1 ms)
2.5 ms per frame in the pursuit window. The view-1 particle prepare already exists as an async task (`asyncParticlePrepared[0]`); check it is used for view 1 in race mode and not only when the mirror launches.

### G6. Collision in pursuits (research only)
participants 4.2 ms is car physics, already parallel on 2 helpers. The queue at 2.5 ms is the next candidate: the predict-queue pipeline hit rate during pursuits. Resolve is inherent (a re-simulation).

## Render thread

### R1. Gather scenery per-command cost (expected -3 to -5 ms)
About 7.3 us per scenery command (13.8 ms for 1887).
- Run `gather_sampler.txt` on the Vita in a dense scene to get the step histogram. The 11-24 track-45 sample had 3.1.23 / 3.1.4 / 3.3.6 / 3.0.21 hottest.
- Candidate: whole-run replay keyed on the run's strip list and resident tokens. Today replay hits 579 runs per frame with 2077 fast strips, so measure what each fast strip still costs.
- Candidate: G2's reused commands carry a "same as last frame" flag, so Gather can reuse last frame's batch output for them.

- Partition 1.06 ms and chains 1.0 ms. Check for an O(n log n) sort that could become an append-ordered merge.
